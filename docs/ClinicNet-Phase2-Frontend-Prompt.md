## Ручная проверка после этой части (без тестов)

- Создать направление через UI (не через API напрямую) внутри одного филиала — от выбора врача до появления записи в расписании принимающего
- То же самое кросс-филиально — убедиться, что выбор специальности/филиала/врача не путает пользователя (это как раз тот UX, который был эталонирован в `multi-branch-schedule.html`)
- Открыть очередь направлений на дашборде — под ролью с ограниченным доступом (`own_branch`) убедиться, что виджет не показывает чужой филиал, даже если бэкенд уже это фильтрует (фронтенд не должен полагаться только на бэкенд-фильтрацию молча — если бэкенд однажды отдаст лишнее, виджет не должен слепо отрисовать)
- Бейдж на расписании — визуально проверить на реальном приёме, созданном из направления, что видно, откуда он взялся
- Заказ анализа из карты → ручной ввод результата → отметка "вне нормы" отображается в карте пациента корректно
